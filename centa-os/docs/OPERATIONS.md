# CENTA REALTY OS 운영·배포 가이드

> 이 문서는 개발 환경에서 **실제로 실행·검증한 것**과 **검증하지 못한 것**을 구분해 적었습니다.

## 1. 서버 준비 (권장: 리눅스 서버 또는 클라우드 VM)
1. Docker와 Docker Compose를 설치합니다.
2. 저장소를 받고 `centa-os` 폴더에 `.env` 파일을 만듭니다.
```bash
cp .env.example .env
openssl rand -base64 48        # 출력값을 AUTH_SECRET 에 넣기
```
3. `.env`에 `DB_PASSWORD`(길고 무작위), `AUTH_SECRET`을 넣습니다. (공공데이터 키·AI 키는 선택. AI 키는 `GEMINI_API_KEY`(무료 가능) 또는 `ANTHROPIC_API_KEY`. 키는 채팅·메일에 붙여넣지 말고 서버의 `.env`에만 입력하세요)
4. 실행: `docker compose up -d --build`
5. 최초 관리자 생성 (1회):
```bash
docker compose exec -e ADMIN_PASSWORD='10자이상-영문숫자포함' -e ADMIN_EMAIL='본인이메일' app npx tsx prisma/seed.ts
```
6. HTTPS: 앱은 `127.0.0.1:3000`에만 열립니다. Caddy 예시(자동 HTTPS):
```
os.내도메인.com {
    reverse_proxy 127.0.0.1:3000
}
```
> ⚠ **미검증**: `Dockerfile`·`docker-compose.yml`은 개발 환경에서 도커 서비스를 실행할 수 없어 빌드·구동을 확인하지 못했습니다. 첫 배포 때 §6 점검표로 확인하세요. 같은 구성(Node 22 + PostgreSQL 16)의 직접 실행(`npm run build && npm start`)은 검증했습니다.

## 2. 로컬 PC(Windows)에서 쓰는 경우
Node.js 22와 PostgreSQL 16 설치 후 `README.md`의 "실행" 절차를 따릅니다. 외부 접속이 필요 없다면 서버 없이도 쓸 수 있으나, **PC 고장에 대비해 백업을 외부(클라우드·외장하드)에 복사**해야 합니다.

## 3. 백업과 복구
- 수동 백업(검증 완료): `./scripts/backup.sh` → `backups/centa_날짜.sql.gz` (최근 30개만 남기고 정리). **업로드된 매물 사진은 DB와 별도 폴더(`UPLOAD_DIR`, 기본 `./uploads`, 도커는 `uploads` 볼륨)에 저장**되며, 같은 스크립트가 `backups/centa_uploads_날짜.tar.gz`로 함께 백업합니다(스크립트 자체의 사진 백업 동작은 검증, 도커 볼륨 경로는 미검증). 사진 파일을 복구하려면 해당 압축을 `UPLOAD_DIR`에 풀어 넣으세요.
- 복구(검증 완료): `./scripts/restore.sh backups/파일.sql.gz` (현재 DB를 덮어쓰므로 `YES` 입력 필요)
- 자동 백업(미검증): `docker-compose.yml`의 `backup` 서비스가 매일 `./backups`에 저장합니다. 이 서비스는 오래된 파일을 **정리하지 않으므로**, 서버 cron에 `scripts/backup.sh`를 등록하거나 주기적으로 직접 정리하세요.
- **개발 환경에서 검증한 것**: 백업 → 별도 DB로 복구 → 11개 주요 테이블 건수 일치, 복구본으로 앱 구동·헬스체크 성공.
- 백업 파일에는 고객·계약 개인정보가 들어 있으니 **암호화된 저장소**에 보관하세요. `.gitignore`로 저장소 업로드는 막혀 있습니다.
- 월 1회는 실제로 복구해 보는 연습을 권장합니다.

## 4. 데이터 이전(기존 자료 → 시스템)
1. **테스트 데이터 구분**: 개발용 샘플은 `isTestData` 표시가 있고 화면에 "테스트" 배지가 붙습니다. 운영 DB에서는 `SEED_DEMO`를 쓰지 마세요. 정리: `npx tsx scripts/purge-test-data.ts`(미리보기) → `--yes`(삭제). 테스트 매물에 연결된 현장방문·계약·정산도 함께 지워지니 **반드시 백업 후** 실행하세요. (복구본에서 시험 완료)
2. **매물**: 기존 사이트 관리자에서 CSV 내보내기 → `매물장 > 가져오기`(미리보기 → 실행). 가져오기로 내부 메모는 덮어쓰지 않습니다.
3. **고객**: 엑셀을 CSV로 저장 → `고객관리 > 가져오기`. 이미 있는 연락처는 건너뜁니다.
4. 이전 후 샘플 5~10건을 원본과 눈으로 대조하세요.

## 5. 보안 운영 수칙
- 관리자 비밀번호 10자 이상(영문+숫자). 직원 퇴사 시 `설정 > 사용자 > 사용 가능` 체크를 해제하면 **기존 로그인도 즉시 끊깁니다**.
- 로그인 5회 연속 실패 시 해당 계정 10분 잠금. `설정 > 감사 로그`에서 `login_fail`, 고객·계약 조회, 내보내기, 외부 AI 전송 기록을 확인합니다.
- 중개보수·정산은 대표 관리자만 볼 수 있습니다. 공인중개사 계정에도 보이지 않습니다.
- 고객용 소개자료·Excel 내보내기는 감사 로그에 남습니다. 소개자료에는 상세주소·소유자·내부 메모·단점이 나오지 않지만, **공개로 지정한 사진은 그대로 나가므로** 사진에 도면·소유자 정보·번호판이 찍혀 있지 않은지 지정 전에 확인하세요.
- 키(`AUTH_SECRET`, API 키)는 `.env`에만 보관하고 채팅·메일·캡처로 공유하지 마세요. 노출되면 즉시 재발급.
- 서버 OS·Docker 이미지는 월 1회 업데이트하세요.

### 홈페이지 자동 동기화 운영
- 주소는 `.env`의 `HOMEPAGE_URL`(비우면 `https://010-8848-7727.com`). 읽는 것은 사이트가 화면에 이미 공개하는 목록·상세 페이지뿐이며 로그인 영역은 사용하지 않습니다. 사이트 부담을 줄이려고 목록은 200건씩, 상세 페이지는 한 번에 최대 40건·0.3초 간격으로만 요청합니다.
- 자동 주기는 서버 프로세스가 떠 있는 동안 1분마다 확인합니다(PC를 끄면 멈춤). 실패해도 다음 주기에 재시도합니다.
- 사이트가 점검 중이거나 응답이 이상하면 **아무것도 바꾸지 않고** 이력에 '실패'만 남깁니다.

### 의존성 취약점(`npm audit`) 판단
- `prisma`(deepmerge-ts), `next`(postcss): 빌드·개발 도구가 **로컬 설정/CSS를 처리**할 때만 해당하고 외부 입력이 닿지 않습니다. 해결책이 **메이저 업그레이드(Next 16, Prisma 7)** 라서 검증 없이 올리지 않았습니다. 다음 정기 업그레이드 때 함께 올릴 것.
- `exceljs`(uuid): 해결책이 구버전(3.4.0)으로의 다운그레이드뿐이며 취약한 호출은 사용하지 않습니다.

## 7. 문제 해결
| 증상 | 조치 |
|---|---|
| 화면에 "문제가 발생했습니다 / 오류 번호: 숫자" | 직원에게 오류 번호를 받아 `docker compose logs app \| grep 오류번호` 로 서버 로그의 원인을 찾습니다(화면에는 내부 정보가 나오지 않습니다) |
| 매물 삭제가 안 됨 | 계약·현장방문 기록이 연결된 매물은 보존을 위해 삭제되지 않습니다. 상태를 '보류'로 바꾸세요 |
| 접속 불가 | `docker compose ps`, `docker compose logs app --tail 100` |
| `/api/health` 503 | DB 컨테이너 상태 확인(`docker compose logs db`), `DB_PASSWORD` 일치 여부 |
| 로그인 잠김 | 10분 대기 |
| 관리자 비밀번호 분실 | 다른 관리자 계정이 있으면 `설정 > 사용자 > 비밀번호 재설정`. 관리자가 한 명뿐이면 DB 수정이 필요합니다(개발자 문의). 시드 스크립트는 기존 계정의 비밀번호를 바꾸지 않습니다 |
| 글자가 깨진 CSV | EUC-KR은 자동 인식됩니다. 그래도 깨지면 "CSV UTF-8"로 다시 저장 |
